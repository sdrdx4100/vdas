# VDAS — 車両データ可視化ダッシュボード

車両データ (CSV / Parquet) をローカルに永続化し、高速に可視化するダッシュボードプラットフォームです。

- **バックエンド**: FastAPI + DuckDB (分析クエリ) + SQLite (メタデータ)
- **フロントエンド**: Plotly.js + Fluent Design (Microsoft) 基調の UI
- **完全ローカル動作**: 外部 CDN 不要 (plotly.js もローカル配信)

## 機能

| タブ | 内容 |
|---|---|
| データ管理 | CSV / Parquet のドラッグ&ドロップアップロード。原本は `data/uploads/` に保存、DuckDB テーブルとして取り込み。**タグ付け** (A社 / B社 / J1939 など): アップロード時の自動付与、チップ式エディタ (既存タグをクリックで追加・入力補完)、複数データセットへの一括追加/削除、タグ絞り込み。プレビュー・削除。**結合 (スティッチ)**: 分割記録された複数ログを順序を指定して1本の連続ログに連結 (列は名前で自動整列・連結順に行位置を振り直し。信号側とGPS側を同じ順で連結すれば行位置対応も保たれる)。 |
| 時系列可視化 | X軸(時間軸) + 複数信号。**信号ごとに個別軸で積み重ねるストリップ表示** (計測ツール風、時間軸は共有でズーム連動) と1軸重ね書きを切替可能。フィルタ条件、自動間引き (最大表示点数指定)、信号名検索。 |
| 全体統計可視化 | 基本統計量 (SUMMARIZE)、ヒストグラム、散布図 (カテゴリ色分け)、相関行列ヒートマップ。 |
| グラフ作成 | **万能チャートビルダー**。グラフ種類 (散布図 / 折れ線 / 棒 / 箱ひげ / ヒストグラム / 密度マップ) を Excel のように選び、X・Y・**色分け** (ギア段・モードなど)・集計 (平均/合計/件数/**割合%**…)・フィルタ条件を自由に組み合わせ。対象は**データセット単体**と**タググループ比較** (タグごとにプールした集合が系列になり、箱ひげ・割合%・分布・動作領域等高線などをグループ間で比較) を切替可能。タググループ比較では母数 (行数) の違いを吸収するため、密度マップは割合%で正規化し、母数依存の集計 (件数・合計) は選べない (平均・中央値・割合%等のみ)。グループ別統計チップを常時表示。すべて自動更新。 |
| 自由分析 | **タググループ統計分析**。①タグでグループを選ぶ (タグ1つ=1グループ) → ②分析の種類をギャラリーから1つ選ぶ → ③最小限の設定、の3ステップで結果は常に1枚。分析は10種類: **集合統計 (ログ単位)** = 各ログの代表値を1標本として箱ひげ+個点・差・95%CI・効果量 / **分布 (割合%)** / **構成比** / **動作領域** (グループ別等高線) / **状態遷移・頻度** (行数・時間・距離あたり) / **区間 (イベント) 分析** = 状態列が指定値の連続区間を1イベントとして抽出し経過時間を比較 (例: shiftinprocess=1 区間の変速所要時間、イベント中の信号平均との散布図も) / **回帰・トレンド** = Y~X の線形回帰の傾き・R² をグループ比較 / **主成分分析 (PCA)** = 多次元信号を標準化して PC1-PC2 平面へ射影しグループの分離を可視化 / **相関** = グループごとの信号間相関行列を横並び比較 / **周波数分析 (振動)** = 加速度などをパワースペクトル (Welch法) で周波数解析し、人が不快に感じる帯域 (既定 4-8Hz) の振動エネルギーをグループ比較 (乗り心地の彼我比較向け)。集合統計には効果量 (Hedges g)・有意差検定 (Welch の t検定・Mann-Whitney) の p値に加え、代表値として平均/中央値/Q75/**ばらつき (標準偏差)**/**ピーク (最大)** を選べる。正規化 (データセット均等・全行プール) とフィルタは全分析共通。1グループなら単体集計。すべて自動更新。 |
| GPS・地図 | **走行軌跡の地図 + 信号波形の連動表示・2走行比較再生**。GPS ログ自体に速度・回転数などの信号列もすべて含まれている場合は、そのデータセット単体で地図・波形の両方が完結し、外部の信号ファイルとのペアは不要 (行数・記録開始時刻のズレの心配も一切ない)。信号ログが別ファイルの場合は、GPS ログは信号ログとは別ファイル (同名の Parquet) として記録される前提で、各ペア内は既定で**行位置 (rowid) で 1:1 対応づけ**るが、GPS・信号の双方で実時刻が分かる場合 (時刻列、または経過時間列とファイル名に埋め込まれた記録開始日時の組み合わせ) は**実際の時刻が最も近い行同士を対応づける方式**に自動で切り替わる。これにより記録開始が数秒ずれていたり行数が完全には一致しなくても正しく揃う (ズレの中央値が大きすぎて信頼できない場合は行位置対応にフォールバック)。信号と GPS のペアは、①**ファイル名の基準名一致** → ②**ファイル名に埋め込まれた記録開始日時**の一致 (例: `260518_191805` と `busloigging_2026-05-18_19-18-05` は同じ日時として一致。命名規則が違っても可) → ③**タグ** (信号「トヨタ」↔ GPS「トヨタ_GPS」) の順で自動突き合わせる。日時が複数一致する場合はタグで正しい相手を優先。手動選択も可能。座標列と緯度経度／ローカル座標を自動判定し、実地図または等尺平面に描画する。単独走行に加え、任意の**比較走行 B**を選ぶと、行数・サンプリング周期・時間軸が異なる A/B の軌跡と同名信号波形を別色で重ねて表示する。比較候補はGPS範囲の重なり・ルート寸法に対する近接距離・タグから順位付けし、**おすすめ比較**として距離と根拠を表示する。会社によって列名が違う信号 (例: `speed` / `車速`) は**信号名の対応付け** (⚙) でグループ登録しておくと、列名が完全一致しなくても同じ信号として重ねて表示できる。A/Bで座標形式 (緯度経度／ローカル座標) が異なる場合は地図への重ね描きだけを諦めて波形比較は続け、走行Bの取得に失敗した場合も走行Aの表示は維持される (どちらか一方の不具合で画面全体が空白になることはない)。同期方式は、A/Bに**独立したシークバー**を持つ時間・手動同期と、GPS近傍点を進行方向に沿って単調対応させる**コース位置同期**から選べる。トンネル等でGPSが欠損した区間は、直前・直後の実測点をアンカーに、車速があれば車速×時間、なければ経過時間で位置と進捗を補間する。補間軌跡は半透明、現在位置には「GPS推定」を表示して実測と区別する。Bの時間オフセット微調整、再生／一時停止・先頭復帰・再生速度変更、地図／波形クリックによる位置選択にも対応する。単独走行では軌跡を任意の信号または**高度 (GPS_z) で色分け**できる。フィルタ・自動間引き対応。地図スタイルは**実地図タイル (OpenStreetMap、要ネット)** と**白地図 (オフライン・ネット不要)** を選べ、タイルを取得できない環境では自動で白地図に切り替わる。 |
| 時系列比較 | **2走行を“同じ条件”に揃えて重ねる汎用比較ビュー**。時刻・行数・サンプリング周期が違っても、横軸(整列軸)を選んで揃えられる: **基準信号を横軸**(速度・RPMなどをXにして「同じ速度域・回転域での挙動」を時刻非依存で比較) と **時間+手動オフセット**(Bをずらして重ねる)。信号ごとに個別軸で積み重ね、走行A/Bを色分けで重ね描き、同じフィルタ条件を両走行に適用する。会社によって列名が違う信号は GPS・地図タブと共通の**信号名の対応付け** (⚙) を使えば、横軸(整列軸)・比較信号・フィルタとも列名が完全一致しなくても対応づけて重ねられる。既存の `/api/datasets/{id}/timeseries` を横軸列を差し替えて走行ごとに叩く構成。※距離/コース位置での整列は次段。 |
| クラスタリング | 選択した信号を K-means で自動クラスタリング (走行状態の自動ラベリング)。結果はデータセットに列として書き戻され、フィルタ・色分け・分布比較にそのまま使える。クラスタプロファイル・色分け散布図・色分け時系列を表示。 |
| 保存ビュー | 可視化状態 (選択列・フィルタ条件・チャート設定) を名前を付けて保存・復元。**ラベルセット** (見たい信号のセット) も保存可能。 |

**操作は「選ぶだけ」**: データセットや信号・条件を変えると、チャートは自動で再描画されます (ボタン押し不要)。データセット選択時は時間軸・代表信号が自動選択され、データ一覧の「📈 時系列」「📊 統計」ボタンから1クリックで可視化に飛べます。自由分析はタグを選ぶと集計・比較が始まります。

ライト / ダークテーマ切替に対応しています。

## セットアップ

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 起動

```bash
python run.py                    # http://127.0.0.1:8710
python run.py --lan              # LAN内の別端末から http://<このPCのIP>:8710
python run.py --port 8000        # ポート変更
python run.py --reload           # 開発用オートリロード
```

`--lan` は `0.0.0.0` で待ち受け、起動時にアクセス先のIPアドレス候補を表示します。Windowsで初回にファイアウォールの確認が出た場合は、信頼できるプライベートネットワークに限って許可してください。

> **注意:** 現在は認証機能がありません。LANから接続できる利用者は、データの閲覧・アップロード・削除を行えます。信頼できないネットワークやインターネットへ直接公開しないでください。

## サンプルデータ

動作確認用の走行データ CSV を生成できます:

```bash
python scripts/generate_sample_data.py sample_drive.csv 60000
```

生成した CSV を「データ管理」タブからアップロードしてください。

## データの保存先

すべて `data/` ディレクトリ配下に永続化されます (環境変数 `VDAS_DATA_DIR` で変更可能):

```
data/
  uploads/       # アップロードされた原本ファイル
  vdas.duckdb    # 取り込み済みデータ (高速クエリ用)
  meta.sqlite    # データセット台帳・保存ビュー・ラベルセット
```

## API

`http://127.0.0.1:8710/docs` で OpenAPI (Swagger) ドキュメントを確認できます。
主要エンドポイント:

- `POST /api/datasets/upload` — ファイル取り込み
- `PUT  /api/datasets/{id}/tags` — タグ更新 / `GET /api/tags` — 全タグ一覧
- `POST /api/datasets/tags/bulk` — 複数データセットへのタグ一括追加/削除
- `POST /api/datasets/{id}/timeseries` — 時系列データ取得 (フィルタ・間引き対応)
- `GET  /api/datasets/{id}/summary` — 全列の基本統計量
- `POST /api/datasets/{id}/histogram` / `correlation` / `scatter`
- `POST /api/compare/histogram` — 複数データセットを共通ビンで分布比較
- `POST /api/compare/groupstats` — グループ列 (ギア段など) で層別した統計量比較
- `POST /api/compare/diff` — 共通信号の自動スキャン (KS 統計量 + 平均Δ% ランキング)
- `POST /api/compare/cdf` — 累積分布 (1% 刻みパーセンタイル) 比較
- `POST /api/compare/curve` — 特性カーブ比較 (X ビン × Y 平均 + P10-P90 帯)
- `POST /api/compare/summary` — 選択信号の統計量比較 (フィルタ適用可)
- `POST /api/compare/cohorts/resolve` — タグ条件から比較グループを解決
- `POST /api/datasets/{id}/chart` — 汎用チャート集計 (scatter / line / bar / box / histogram / heatmap、色分け・割合%集計・フィルタ対応)
- `POST /api/chart/groups` — タググループ横断の汎用チャート集計 (系列=グループ、プールは UNION ALL)
- `POST /api/compare/histogram` — `as_category` で構成比 (割合%) 比較
- `POST /api/compare/cohorts/histogram` — タググループ別の1次元分布比較 (`as_category` 対応)
- `POST /api/compare/cohorts/histogram2d` — タググループ別の2次元密度比較
- `POST /api/compare/cohorts/transitions` — タググループ別の状態遷移頻度比較
- `POST /api/compare/cohorts/events` — 状態区間 (イベント) の経過時間・信号平均比較
- `POST /api/compare/cohorts/regression` — グループ別の線形回帰 (傾き・R²)
- `POST /api/compare/cohorts/pca` — 主成分分析 (PC1-PC2 射影・寄与率・ローディング)
- `POST /api/compare/cohorts/correlation` — グループ別の信号間相関行列
- `POST /api/compare/cohorts/spectrum` — 周波数分析 (Welch PSD・不快帯域エネルギー)
- `GET /api/gps/pairs` — 信号データ × GPS データの自動ペア一覧 (同名判定)
- `GET /api/gps/datasets` — 緯度・経度列を持つ GPS データセット一覧
- `GET /api/gps/{id}/similar` — GPS範囲・近接距離・タグによる比較走行候補
- `POST /api/gps/{id}/track` — GPS 軌跡と信号を行位置で結合した地図＋波形データ
- `POST /api/datasets/{id}/cluster` — K-means クラスタリング (結果列の書き戻し)
- `GET/POST/DELETE /api/views` — 保存ビュー (時系列 / 統計 / 比較)
- `GET/POST/DELETE /api/labelsets` — ラベルセット
- `GET/POST/DELETE /api/signal-aliases` — 信号名エイリアス (会社ごとに異なる列名のグループ登録)

## 開発・テスト

開発用依存関係をインストールします。

```bash
pip install -r requirements-dev.txt
```

テストと静的チェックは次のコマンドで実行できます。テスト用DBは一時ディレクトリに作成され、通常の `data/` は変更しません。

```bash
pytest --cov=app --cov-report=term-missing
ruff check app scripts tests run.py
```

GitHub Actionsでは Python 3.12 / 3.13 の両方で静的チェックとテストを実行し、バックエンドのカバレッジ75%以上を必須としています。
